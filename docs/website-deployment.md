# Secblitz website

The static download page at https://secblitz.lol, served by Cloudflare Pages
(project `secblitz`). It has no dependencies and makes no third-party requests.
The normal deploy is automatic: `.github/workflows/publish-website.yml` runs
after a release is published, as described in `docs/RELEASING.md`, step 9.
This page covers how the site is built and the manual path for emergencies.

## Files

| File | Purpose |
| --- | --- |
| `website/index.html` | The page |
| `website/404.html` | Branded not-found page |
| `website/styles.css` | All styles |
| `website/app.js` | Theme button label and checksum copy |
| `website/theme.js` | Applies the saved theme before the page paints |
| `website/_headers` | CSP, security headers, caching |
| `website/releases/stable.json` | The signed update feed (copied from the release) |
| `website/assets/` | Screenshots, icons and self-hosted fonts (with OFL.txt) |

Screenshots and the favicon are generated by `scripts/build-site-assets.py`;
`--check` fails when a generated file is out of date.

## How the site is built

Never upload `website/` directly. `scripts/assemble-site.py` builds `dist/pages`:

1. Writes the real setup checksum and size into the page.
2. Runs `prepare-pages.py --require-feed`, which checks the feed signature
   against `assets/update-public-key.hex`, the version and the setup hash.
3. Copies only the files named in the `stage-pages.py` allowlist. Content-hashed
   asset names are checked against their bytes, so a stale or swapped file fails.

Older downloads stay published. `scripts/historical-downloads.py fetch` downloads
them and checks each one against `scripts/historical-downloads.sha256`. When a
release replaces the current version, append its setup and exe hashes to that
file and add the version to `HISTORICAL` in `stage-pages.py`.

Cloudflare Pages limits files to 25 MiB.

## Manual deploy (emergencies only)

Authenticate with `npx --yes wrangler@4.147.0 login`, or put a Pages-only token
in the process environment. Never put credentials in a file in the repository.

```sh
python3 scripts/historical-downloads.py fetch --dest "$R/historical"
python3 scripts/assemble-site.py --version X.Y.Z --assets "$R/release-assets" \
  --historical "$R/historical" --output dist/pages
CLOUDFLARE_ACCOUNT_ID=<account id> npx --yes wrangler@4.147.0 pages deploy dist/pages \
  --project-name secblitz --branch main
python3 scripts/verify-live-site.py --site dist/pages --version X.Y.Z
python3 scripts/verify-live-site.py --site dist/pages --version X.Y.Z --origin https://beacons.lol
```

`$R/release-assets` holds the setup, the portable exe, `SHA256SUMS` and the
signed `stable.json`. The live check retries for a few minutes while the edge
catches up, then names every file that differs.

## Domains

`secblitz.lol` is the primary origin. The old `beacons.lol` origin must keep
serving `/releases/*` and `/downloads/*` directly, without redirects: copies
older than 0.5.0 were built to check that origin for updates. Both domains point
at the same Pages project, so one deploy updates both.

Zone-level redirects (Pages cannot redirect by domain):

| Zone | Match | Target | Status |
| --- | --- | --- | --- |
| `beacons.lol` | `http.host eq "beacons.lol" and http.request.uri.path eq "/"` | `https://secblitz.lol/` | 301 |
| `secblitz.lol` | `http.host eq "www.secblitz.lol"` | `concat("https://secblitz.lol", http.request.uri.path)` | 301 |

The feed is served with `Cache-Control: no-store`. Downloads use versioned
names, so the zone's 4 hour browser cache on them is harmless. Turn off
Cloudflare Web Analytics in the zone: its injected beacon is blocked by the CSP.
