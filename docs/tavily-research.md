# Advanced-search research supplement

Five Tavily `search_depth: advanced` searches were executed for this project. The credential was used only for research requests and is not part of the application, website, or build. No device inventory, account details, or passwords were sent. Search results are discovery aids, not executable policy.

## Searches and decisions

1. **Windows 10/11 consumer security baselines and compatibility.** Microsoft’s [security baselines guide](https://learn.microsoft.com/en-us/windows/security/operating-system-security/device-management/windows-security-configuration-framework/windows-security-baselines) describes thousands of available policy settings. Enterprise baseline settings are not universally appropriate for unmanaged home computers. Secblitz implements a bounded, reversible subset; research coverage must not be confused with implementation coverage.
2. **ASR, ransomware, and controlled folder access.** The [ASR overview](https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-overview) and [CFA configuration guide](https://learn.microsoft.com/en-us/defender-endpoint/controlled-folder-access-configure) support assessment in audit mode before blocking. Automatic enforcement without application compatibility evidence can interrupt legitimate work. Future approval-based functionality should preserve per-rule modes and exclusions and never label audit mode as prevention.
3. **SMB, NTLM, RDP, and legacy compatibility.** Search returned mostly Microsoft Q&A discussions, including advice to weaken authentication/signing. Those answers were deliberately excluded as normative policy. Preserve existing stronger settings; warn about legacy protocols and exposed remote access. Do not disable SMB signing or NTLM protections to make a scan pass. The primary-source matrix in `hardening-research.md` remains authoritative for design decisions.
4. **Password-manager installation and password generation.** Bitwarden’s [official downloads](https://bitwarden.com/download/) and [browser-extension guidance](https://bitwarden.com/help/getting-started-browserext/) distinguish installation from vault setup, saving a generated password, and actually changing the account password. Secblitz must not claim any of those subsequent steps happened. Current vendor OS requirements may differ from Secblitz’s Windows 10/11 support; package applicability must be honored rather than bypassed. The desktop client, not Bitwarden’s self-hosted server deployment script, is the intended companion.
5. **LSA protection, Credential Guard, memory integrity, and encryption.** [LSA protection](https://learn.microsoft.com/en-us/windows-server/security/credentials-protection-and-management/configuring-additional-lsa-protection), [BitLocker](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker), and [device-security guidance](https://support.microsoft.com/en-us/windows/security/windows-security/device-security-in-the-windows-security-app) reinforce hardware, driver, authentication, and recovery dependencies. Silent firmware, recovery-key, or UEFI-lock changes are unsuitable for a reversible low-disruption default.

## Personalization boundary

The current implementation tailors eligibility using observed platform capabilities, management state, policy ownership, security-provider presence, and current values. It does not infer a person's complete workflows or guarantee compatibility with all printers, games, accessibility applications, NAS devices, or remote-support tools. Deeper personalization requires explicit user context and real compatibility testing; it cannot be established merely by adding more registry writes.

The broad catalog and source-by-source mapping are in [hardening-research.md](hardening-research.md). Only the implemented controls listed there are applied. Hardware-backed protections, broad software updating, ASR/CFA enforcement, backup provisioning, browser extension setup, and account MFA setup remain recommendations or future work.
