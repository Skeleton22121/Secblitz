## Wave 1 fixed findings

1. **Misleading clean exit (medium):** the CLI considered only result errors/conflicts/pending states. An audit containing attention/unknown findings, or skipped controls, printed Complete and exited 0. `needs_review` now considers both results and findings; attention, unknown, skipped, errors, conflicts, pending, and unrecognized statuses print Review needed and exit 2. Successful informational statuses remain 0. Execution failures remain 1. JSON retains its raw schema and now shares the same exit semantics. No CLI HTML export exists or is advertised in command help.
2. **Incomplete consent (medium):** `--yes` accepted package/source agreements without telling users. The five-language help and missing-consent error now disclose download/install from the Microsoft WinGet repository, Bitwarden package licenses/agreements and WinGet source agreements, and the choice of another password manager. The disclosure is also shown before execution. Optional installation still runs only through the explicit command, before application elevation.
3. **Terminal injection gaps (medium):** status labels, history status suffixes and progress messages bypassed the sanitizer. All now sanitize text before styling/rendering. Sanitization also removes directional marks and Unicode line/paragraph separators. Raw JSON is deliberately unchanged. Regression tests exercise malicious controls in every row field without generating a password.
4. **Accessibility preference ignored (low):** terminal animation used only the command flag and TTY detection. Windows client-area-animation preferences now gate animation through `SystemParametersInfoW`; query failure disables animation. `--no-animation` remains available; redirected output is static.
5. **Evidence corruption during translation (medium):** substring replacement could translate `ok` within `Notebook`, or `info` within `information`. Word boundaries now prevent those substitutions; tests cover names and identifiers. Unknown firewall control IDs no longer get mislabeled as inbound-block controls.
6. **Release URL validation too permissive (low):** on HTTPS hosting, relative and protocol-relative URLs passed despite documentation allowing only absolute HTTPS URLs or same-origin absolute paths. Validation now enforces those forms and requires the digest to be a string. Credentials, fragments and unsafe protocols remain rejected. Default release configuration stays null/disabled, with no invented digest or artifact.
7. **Browser feature fallback (low):** missing `matchMedia` or its modern event API could abort later UI initialization. Missing motion APIs now select a static demo; legacy change listeners are supported.

## Review conclusions and remaining integration work

- **Localization:** the wave-1 diagnostic catalog gaps were addressed in wave 2 above. Machine-readable JSON is deliberately language-neutral. Native/third-party exceptions can retain their original language; application-authored headings and advice are translated.
- **Service-owner handoff resolved:** service printing was removed by its owner and the structured state API is integrated with localized CLI presentation. Windows runtime confirmation of this new presentation remains with the runtime reviewer.
- **UAC:** arguments are reconstructed from parsed fixed choices, not arbitrary OS strings; JSON refuses elevation from an unelevated terminal because the separate console cannot supply redirected stdout. ShellExecute failure, missing process handle, wait failure and exit-code retrieval failure propagate; child exit codes are returned. Native UAC approval/cancellation and wait behavior need Windows runtime validation.
- **Double-click:** no-command launch still applies; own-console detection pauses both the original no-argument process and the elevated no-command child carrying language options. Redirected/nonterminal stdin does not block. Native console ownership needs Windows runtime validation.
- **Password:** reviewed 24 independent OS-random six-bit characters (144 generated bits), no class-repair/modulo bias, no existing-password inspection, no clipboard/report/journal route, and refusal to output to redirected stdout. Generation intentionally displays a secret in the interactive terminal; terminal capture/scrollback are not prevented. No password was generated or exposed during review.
- **Tool implementation:** retained fixed package/source arguments, verified repository metadata, registered App Installer resolution, non-elevated desktop-user restriction, bounded capture/deadline, no hash bypass, post-install detection, and meaningful existing tests. No installer was run. Windows execution and WinGet compatibility remain runtime validation tasks.
- **Website claims:** 12 controls correspond to four Defender preferences, six firewall profile preferences and two UAC preferences. Broader checks are advisory. Site states Windows 10/11 x64, administrator access, no-command apply, conflict-aware undo limitations, optional network installation, Windows lifecycle caveats and development-preview status. The terminal illustration explicitly disclaims live results. No actual release validation, signature, or published hash is claimed. URL/digest syntax checks cannot establish artifact existence or authenticity.
- **Accessibility/color:** labels accompany terminal status colors. Website uses native keyboard controls and visible focus. Browser checks cover skip-link focus, privacy disclosure, reduced motion and representative text contrast (at least 4.5:1 on nearest solid surfaces). This is not a full WCAG audit; gradients and all assistive-technology combinations were not automatically audited.
